# 0.34.0 实施与验收台账

当前源码准备版本为 **0.34.0**，在已发布的 0.33.0 基线上完善字典请求边界，并通过显式可选 `/business` 提供字典列策略与本地语义合计。采用现有列值、字典 Provider 和固定行协议，不引入 UI、传输层或数值引擎。以下本轮状态与历史发布记录分别保留。

## 0.34.0 本轮实现范围

| 范围 | 已实现内容 | 边界 |
| --- | --- | --- |
| 字典缓存所有权 | 同 key 排队/在途复用；单键及全量失效隔离旧响应并结束等待；显式 prime 优先；销毁取消与错误观察隔离 | 缺失 key 受相同 TTL/LRU 限制，失败不缓存；组织、语言、权限范围由宿主持有 |

验收范围以各配方明确列出的 API 和场景为准，自动验证结果见上方本轮记录；更广的行业工作流、数据规模或完整工作簿平台需求须独立评审：

- [工作台](/recipes/workbench)采用页面内区域及原生控件；诊断是公开 API 的手动快照，未知配置来源/限制原因如实显示未知，不推断完整因果链。冲突“保留本地”不自动合并服务端版本，宿主负责版本处理与 CAS。
- [偏好](/recipes/enterprise-preferences)提供身份、存储和迁移协议；共享偏好的权限审批、组织工作流和更多历史版本适配属于宿主或后续需求。
- [排序](/recipes/row-presentation)的默认托管模式保持扁平数据；可选排序控制器提供多行/树及独立历史。保存端需原子执行 `context.operations` 或 `context.plan.after`，不能用单意图写入假定复杂撤销已完成。
- [服务端 Store](/recipes/server-side-store)展示 route 活动页与缓存投影，不提供全树任意 offset、跨层原子快照或服务端 Pivot；服务端负责权限、聚合和原子事务。
- [多范围](/recipes/multi-range)限于当前模型与可见列，最多 32 个矩形、单次操作 100000 格；不提供跨查询持久选区或多个填充柄。
- [分析](/recipes/analysis)面板统计当前模型已加载的普通行，不等于筛选后可见行或服务端全量；超出 10000 条时明确提示截取。纯计算内核超限抛错。图表展示前 40 组，完整结果使用分页表格。
- [列值政策](/recipes/column-values)只统一同步入库与输出；`rows.transact` 继续按可信数据处理。[导入计划](/recipes/import-preview)有明确行数、单元格和快照上限，新记录映射拒绝歧义 getter/setter。XLSX typed 直通保留宿主引擎返回的类型，不承诺恢复源文件已丢失的编号精度。
- 公式仅逐记录计算有限算术与 SUM/MIN/MAX/AVG，结果 ID 是安全单层属性，输入可引用安全嵌套路径；不执行 JavaScript，不提供 A1 跨行/跨表、Excel 工作簿或服务器公式引擎。BI 联动、外部图表引擎、更多函数以及双边等价性能基准均可另行评估。
