# 1.0 就绪评估

本页评估 **0.42.0** 之后进入 1.0 候选阶段的条件，不修改 npm 版本，也不代表已经发布 1.0。更新日期：**2026-11-15**。

## 判断标准

1.0 承诺的是已声明支持范围内的兼容与维护责任。功能数量、通过用例总数或某次性能结果都不能单独证明成熟度。新增能力只在存在实际业务需求且边界明确时继续扩展。

| 条件 | 当前事实 | 发布前还需要的证据 |
| --- | --- | --- |
| 能力覆盖 | 主列表/明细、动态列、查询选择、事务编辑、树/分组、分析、导入和状态恢复已有实现 | 依据当前[能力路线](/advanced/roadmap)确认对外支持范围，不把可选实现写成全场景兼容 |
| 工程防线 | `verify` 覆盖静态、覆盖率、公开契约、真实消费、构建、预算、产物、示例和文档；E2E 独立执行 | 当前候选同一份产物的完整日志、版本、摘要和退出码 |
| 兼容 | peer 声明 Vue ≥3.2、React/ReactDOM ≥18 | 隔离消费者的固定版本矩阵；不能以主锁文件测试代表整个 peer 范围 |
| 复杂交互 | 库级三浏览器覆盖布局、输入、选择、缓存、层级与工作台；RobotAdmin 有业务浏览器回归 | 将真实页面的动态列、拖宽、弹窗、tags 与偏好隔离串成连续操作链 |
| 长期运行 | 已有大表、持续滚动、更新与重复挂载门禁 | 独立长稳报告中的保留堆、DOM、监听与缓存趋势；短检与长检分别记录 |
| 真实业务 | RobotAdmin 产销示例展示契约与组合方式；服务端 Store 有模拟故障用例 | 真实接口、多账号权限、并发版本、部分提交、聚合与导出范围 UAT；至少一次业务升级和回退演练 |
| 无障碍 | ARIA、键盘、IME、焦点和高对比自动化已有实现 | NVDA/JAWS/VoiceOver 及目标缩放、输入法的真实任务验收，详见[人工清单](/advanced/accessibility#尚需真实读屏软件验收) |
| 长期契约 | API 快照、状态 schema v2、稳定错误语义、迁移说明与授权流程已有 | 发布评审明确稳定入口、兼容/弃用策略、版本支持及实际缺陷响应范围 |

## 当前结论

当前有能力完整且受工程门禁保护的产品基础。兼容矩阵、复合交互及实际 30 分钟长稳已在本地完成，具备进入 1.0 候选评审的工程证据。**尚无多个真实生产业务完成验收及升级/回退演练的充分证据，不能仅因自动化通过就宣布满足正式 1.0 的全部条件。**

正式 1.0 仍需明确业务验收与支持范围；真实辅助技术尚未验收时应保持标注，不对外宣称相应兼容认证。目前暂无相应人工验收环境，继续记录待人工。远端 GitHub Actions 还需在账号恢复执行能力后复跑，不能把本地通过写成远端通过。

发布决定以维护者对上述范围和证据的评审为准。本文不通过增加新框架、重写渲染引擎或扩展全部竞品能力来设置额外门槛。
