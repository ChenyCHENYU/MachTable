# 当前能力与成熟度路线

本页以 **0.42.0** 为能力基线。0.28 的 API 收口和复杂度治理已完成；后续版本也已交付高级筛选、修改审阅、服务端 Store、分析和多范围能力，不再把这些实现列为待办。各版本原始验收记录保留在[历史台账](/advanced/implementation-plan)，发布判断见 [1.0 就绪评估](/advanced/release-readiness)。

## 已具备的能力

| 方向 | 当前实现 | 接入与边界 |
| --- | --- | --- |
| 主列表与紧凑明细 | Vue/React 默认 `list`，同页小表使用 `detail`；序号、分页、表头工具和内容高度按场景提供默认值 | [场景与配置](/guide/configuration)；单表显式配置优先 |
| 列布局 | 有界内容测宽、按比例铺满、完整表头最小宽度、固定区域、目标列独立调宽 | [列状态](/recipes/column-state)；结构列保持紧凑，复杂自定义表头由宿主提供最小宽度 |
| 查询与选择 | 动态列、服务端分页、取消、旧响应隔离、重试、显式跨页选择和全查询选择规则 | [远程查询](/recipes/remote-query)；全查询选择不等于浏览器持有全部行 |
| 编辑与审阅 | 单元格/整行事务、异步校验、批量通知、撤销重做、部分保存、冲突与修改审阅 | [批量保存](/recipes/batch-save)、[工作台](/recipes/workbench)；服务端负责权限、原子写入和版本校验 |
| 数据规模 | 行列虚拟化、变高行索引、增量事务、有界随机块、Worker 与性能诊断 | [性能](/advanced/performance)；真实吞吐仍取决于业务列、设备和接口 |
| 层级数据 | 本地树/分组、懒加载、服务端 route 分页、聚合刷新、CAS 和层级选择 | [服务端 Store](/recipes/server-side-store)；不同 route 不承诺全树原子快照 |
| 按需分析 | 高级过滤、Pivot、公式、图表、多范围和导入预览 | [分析](/recipes/analysis)、[多范围](/recipes/multi-range)、[导入](/recipes/import-preview)；各模块有资源上限，不是完整电子表格 |
| 状态与隔离 | 版本化状态、命名视图、用户/组织偏好、字段迁移与异步恢复保护 | [企业偏好](/recipes/enterprise-preferences)；身份和业务权限由应用提供 |
| 工程防线 | API 快照、类型/双模块真实消费、复杂度、依赖、包体、产物、文档和三浏览器回归 | [质量门禁](/advanced/quality-gates)；通过状态以实际命令和报告为准 |

字典插件、HTTP 客户端和业务身份由项目组合。表格接收普通列、选项和 formatter，不识别字典包，也不加入另一套应用控制器。

## 当前优先级

1. **连续业务操作回归。** 将动态列、拖宽/固定、滚动、编辑、弹窗、tags 往返和身份隔离放入同一操作链，补充单项测试之间的边界。
2. **长时间资源稳定性。** 在独立测试进程测量强制 GC 后的保留堆、DOM、监听与缓存趋势；固定轮次检查继续作为快速门禁，不冒充长期无泄漏证明。
3. **兼容承诺与证据一致。** 用隔离消费者验证最低声明版本、项目主用版本和已选定的当前稳定版本；框架生命周期检查与真实浏览器布局检查分别记录。
4. **真实业务验收。** 使用真实接口验证查询、全查询选择、并发编辑、部分成功、导出和聚合口径；保留至少两个业务项目的接入、升级和恢复记录。
5. **维护契约。** 同步当前指南、支持范围、状态升级、错误语义和回归修复流程，按证据决定进入 1.0 候选阶段。

## 继续扩展的原则

结合已归档的产销场景，下一批使用侧配方可优先选择以下两类，复用当前能力即可，不作为 1.0 缺少内核功能的判断：

- **三级主从联动**：浇次 → 炉次 → 钢坯，明确换主单、子选择清理、未保存确认与晚到响应隔离；应用组合现有查询、资源与离开保护。
- **动态周期与权威汇总**：动态月份/周期列与明细、小计、总计，明确可编辑/可选行及汇总来源；后端权威合计原样展示，避免二次求和。

后续公共能力继续遵循：

- 先复用现有配置、事件、工作流和可选模块，只有跨项目重复且职责明确的能力才进入公共 API。
- 服务端全量导出、批量业务任务的进度/取消/结果由真实后端契约驱动；前端示例不模拟成已完成的生产任务平台。
- 复杂打印模板、完整工作簿和协作按独立产品需求评估，保持基础表格的加载成本与维护边界。
- 默认消费入口继续受现有预算约束。拆分以真实消费图收益为依据，不能靠重复 Lite 入口、碎片函数或放宽质量阈值换取表面通过。

## 1.0 的含义

1.0 表示对支持范围内的公共契约承担长期兼容责任。它不要求复制竞品全部功能，也不表示所有浏览器、辅助技术和任意业务组合都已验收。

正式发布前应完成：

- 当前公开入口、默认行为、状态 schema、事件和错误语义的冻结评审；
- 当前候选产物的工程门禁、兼容矩阵、复合业务回归与长稳验证；
- 至少一次真实业务升级与回退演练，以及代表性业务 UAT；
- 对真实读屏、目标设备和服务端强一致等未验收范围作出明确发布说明；
- 可执行的授权、版本维护和缺陷响应边界。

自动化已完成、人工仍待验收和业务不在支持范围是三种不同状态。完整清单与当前结论见 [1.0 就绪评估](/advanced/release-readiness)。
