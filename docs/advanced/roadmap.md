# 0.23 能力边界与后续路线

MachTable 0.23 面向复杂中后台、工业台账、订单/工单和运营工作台，仍处于 0.x 产品打磨阶段。本轮没有用中间版本号制造发布噪音，而是把原计划的 0.20—0.23 能力合并为一个经过完整门禁的 0.23.0。

## 已交付路线

| 阶段 | 目标 | 0.23 验收结果 |
| --- | --- | --- |
| 0.20 | API 治理与增量失效 | 8 个惰性领域、兼容策略、跨包快照、配置单批次提交、update-only 快路径 |
| 0.21 | 构建与发布工程 | runtime-only 快速构建、无 sourcemap 发布构建、gzip 与解压产物预算 |
| 0.22 | 远程资源与内存 | 并发上限、优先队列、方向预取、重试抖动、共享 Long Tasks Observer |
| 0.23 | 回归证据 | 语义契约、100k×100、500 列、连续滚动、重复挂载/销毁与多浏览器门禁 |

此前 0.10—0.19 已完成分层配置、远程分页、查询级选择、业务列/字典、编辑保存闭环、列工作台、权限动作、懒加载树、主从明细、XLSX 可选包、完整状态、列宽拖动记忆、Worker 边界和双向虚拟化。详见各包 Changelog。

## 0.23 适用范围

| 场景 | 当前能力 |
| --- | --- |
| 高频后台列表 | 排序/过滤/分页/选择、列偏好、状态恢复、工具栏与 Vue/React 工作流 |
| 复杂录入 | 单元格/整行编辑、异步校验、撤销重做、脏数据、部分保存与冲突处理 |
| 大数据浏览 | 行列双虚拟化、变量行高 Fenwick 索引、随机块 LRU、并发调度、可选 Worker |
| 层级与分析展示 | 树/懒加载树、分组聚合、主从详情、固定行、汇总与行列合并 |
| 企业治理 | 分层默认配置、版本化状态、稳定错误码、API/复杂度/体积/覆盖率/浏览器门禁 |

在上述目标范围内，0.23 可以进入真实企业项目试点与持续 UAT，但这不等同于 AG Grid Enterprise 的完整 SSRM/Pivot/图表生态，也不构成 1.0 API 冻结声明。

## 明确不塞入默认 Core

| 能力 | 决策 |
| --- | --- |
| Pivot、公式引擎、图表联动 | 等真实业务与安全模型成立后做独立 Feature/包，不进入默认 chunk |
| 完整服务端分组 Store | 先以真实接口冻结 group key、child count、aggregate 和事务协议 |
| Canvas 超密集只读分析 | 与 DOM 业务组件、编辑和可访问性目标冲突，应独立选型 |
| 多人协同编辑 | 需要独立版本、锁、合并和审计协议，不以普通 GridApi 拼接 |

## 下一阶段按证据推进

1. 在至少两个真实项目记录查询、编辑、冲突、懒加载树、列工作台和随机块 UAT。
2. 建立 Linux 基准历史趋势和稳定的跨浏览器视觉基线；绝对耗时只作保守上限，回归以同环境相对变化为主。
3. 完成 NVDA/VoiceOver 人工读屏矩阵和键盘业务路径复核。
4. 根据真实服务端接口决定是否建设分组 Store Feature；没有协议证据前不复制 AG SSRM。
5. 1.0 前审计 126 个公开成员（含 8 个领域入口）：保留高频直接命令，低频能力迁移到领域/Feature，并提供自动迁移清单。

只有真实 UAT、API 迁移、性能/内存、无障碍、安全、视觉回归和发布回滚证据持续稳定后，才讨论 1.0。
