# 0.9 能力边界与路线图

MachTable 0.9 的定位是：复杂中后台、工业台账、订单/工单和运营工作台可生产接入的数据网格内核。它已经具备企业项目需要的类型、生命周期、状态、错误治理、可访问性和自动化门禁，但不宣称覆盖大型商业网格的全部高级分析能力。

## 0.9 已完成

| 维度 | 能力 |
| --- | --- |
| 大数据 | 行/列双虚拟化、变高行定位、10 万行 × 100 列浏览器预算、高频异步事务合批 |
| 数据模型 | 客户端排序过滤、分页、可取消/重试无限数据源、树、分组聚合、主从明细 |
| 编辑 | 单元格就地对勾/取消、整行暂存与统一校验提交、撤销重做、脏数据、并发保存确认、回滚 |
| 操作列 | 任意动作、查看/编辑/删除预设、整行保存/取消切换、菜单/抽屉/全展开三种溢出模式 |
| 状态 | 版本化 `GridState`、列状态存储、初始状态、稳定行 ID 保持 |
| DX | 单框架包安装、规范 `MachTable` 名称、Vue 全局/异步默认值、React Provider、字段路径列助手、企业预设 |
| 治理 | 稳定错误码、诊断快照、生命周期泄漏检查、三浏览器 E2E、exports/消费端类型/体积/覆盖率门禁 |
| 可访问性 | grid/treegrid 语义、活动后代、表头与单元格键盘、异步编辑忙碌/错误状态 |

## 已知边界

| 场景 | 0.9 选择 |
| --- | --- |
| 服务端行分组/聚合下推 | 尚无完整 SSRM；无限模式是顺序块模型 |
| Pivot / 透视分析 | 未实现，建议服务端预聚合或专项立项 |
| XLSX 多 Sheet | Core 只内置安全 CSV；通过业务层按需集成 SheetJS 等工具，避免增加所有用户体积 |
| Canvas 渲染 | DOM 虚拟化优先，便于可访问性和业务组件嵌入；超密集只读画布不是当前目标 |
| 树形跨层拖拽 | 只发业务事件，不自动改父子关系 |
| 视觉回归 | 功能 E2E 已覆盖，像素级主题矩阵仍待建立 |

## 1.0 前优先级

### P0：契约稳定

- 公开 API 兼容清单和废弃周期；移除 `RobotGrid` 前提供完整迁移窗口；
- 对 GridState/错误码建立冻结测试与迁移说明；
- 补齐真实读屏软件矩阵和 WCAG 对比度审计；
- 建立发布候选项目验证清单与回滚演练。

### P1：高价值业务能力

- 服务端缓存策略、请求超时与可插拔块缓存；
- 批量跨行编辑面板、服务端冲突标记和失败单元格跨视口定位；
- 列组整体移动、树形 DnD 协议、可配置 Enter 导航；
- 可选 XLSX 扩展包，不进入零依赖 Core。

### P2：独立立项

- SSRM、Pivot、Worker 排序、Canvas、协同编辑。它们会显著改变包体积和架构，应由真实业务需求与独立性能指标驱动，而不是为了能力表打勾。

## 是否达到企业级

在“复杂业务数据录入与浏览组件”的目标范围内，0.9 已达到企业接入候选标准：有稳定类型、错误隔离、可恢复状态、资源销毁、安全默认值和 CI 门禁。正式大规模推广前仍应由真实项目完成 UAT、无障碍抽查、性能画像和回滚演练；涉及 SSRM、Pivot 或超大分析型报表时，应按上表边界重新选型。
